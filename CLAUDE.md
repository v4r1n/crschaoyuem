# Project instructions

## Mission

Build and maintain CRS Yuem-Kuen System, a production-usable internal equipment borrowing system for small and medium organizations. Use `CRS Yuem-Kuen` as the short brand and `CRS Yuem-Kuen System` as the full product name. The runtime stack is Google Apps Script, Google Sheets, Google Drive, HTML/CSS/JavaScript, and Bootstrap 5. The product language is Thai.

## Non-negotiable rules

- Keep the runtime free of paid infrastructure, VPS, Docker, and external databases.
- Treat one Equipment row as one physical asset. `quantity` is always `1`; identical assets share an SKU.
- Use the canonical English enum values from `src/Constants.gs` in storage and translate only in the UI.
- Derive visitor identity only through the server-side Google OAuth 2.0/OpenID Connect Authorization Code flow. Verify the returned ID token's signature, issuer, audience, expiry, nonce, and authoritative email on the backend. Never use `Session.getActiveUser()`, `Session.getEffectiveUser()`, or an unverified client-supplied email/role as the visitor.
- Protect sign-in with Apps Script state, nonce, PKCE, one-time flow records, and a short-lived opaque application session. Store auth state only in `ScriptCache` under hashes of unguessable secrets; never use deployer-shared `UserProperties`, URL tokens, cookies, `localStorage`, or `sessionStorage` for the application session.
- Deny access when the authorization proof or application session is missing, invalid, expired, replayed, issued to another OAuth client, outside `ALLOWED_DOMAINS`, non-authoritative for the asserted email, absent from Users, inactive, or insufficiently privileged. Never auto-provision a visitor.
- Enforce authorization in every server mutation. Hiding a button is not authorization.
- Put every state-changing workflow under `LockService.getScriptLock()`, re-read authoritative rows inside the lock, and validate the exact source state.
- Never hard-delete Equipment, Borrow, Users, Categories, IncludedItems, or History records. Use lifecycle statuses.
- History is append-only and generated by domain services, never by the browser.
- Use bulk `getValues()`/`setValues()` and header-based records. Do not read a sheet cell-by-cell.
- Cache only performance data. Never use cached roles, availability, active-loan state, or counters for correctness.
- Internal server helpers end in `_`; public RPC functions are narrow, guarded wrappers.
- Do not introduce unfinished runtime placeholders. Spreadsheet ID, Drive folder ID, web-app URL, allowed domains, Google Web OAuth Client ID and secret, authentication TTLs, and initial admin email remain deployment configuration in Script Properties; credentials and resource IDs must never be hardcoded or committed.

## V1 state model

```text
Borrow:    PENDING_APPROVAL -> APPROVED -> CHECKED_OUT -> RETURN_REQUESTED -> RETURNED
Equipment: AVAILABLE        -> PENDING  -> RESERVED     -> BORROWED         -> RETURNING
```

Alternate transitions are `PENDING_APPROVAL -> REJECTED`, admin direct return from `CHECKED_OUT`, and inspected return to `AVAILABLE`, `DAMAGED`, `MAINTENANCE`, or `LOST`. Overdue is derived from due date and is never persisted as the primary status.

## Source layout

- `src/*.gs`: Apps Script controllers, services, validation, repositories, setup, and migrations.
- `src/*.html`: one HTML-service SPA shell plus server-included styles, components, views, and scripts.
- `docs/`: architecture, schema, workflows, operations, decisions, migration notes, memory, and changelog.
- `tests/`: local contract/static tests and the manual acceptance matrix.

## Coding conventions

- JavaScript must be compatible with the Apps Script V8 runtime and should not require a bundler.
- Store instants as ISO-8601 UTC strings and business dates as `yyyy-MM-dd` in `Asia/Bangkok`.
- Sanitize user-controlled Sheet text against formula injection and render it with `textContent` or escaped templates.
- Return serializable plain objects only; `google.script.run` cannot transport `Date` values.
- User-facing errors are concise Thai messages with stable error codes and a request ID; detailed stacks stay in execution logs.
- Commits follow Conventional Commits. Do not create Git tags unless the user later requests one.

## Session End Protocol

Complete this checklist at the end of every phase:

1. Run the checks relevant to the phase and record the result in `docs/MEMORY.md`.
2. Update `docs/MEMORY.md` with completed scope, current constraints, and the exact next phase.
3. Update `docs/CHANGELOG.md` under `Unreleased`.
4. Add or supersede decisions in `docs/DECISIONS.md` when architecture or contracts changed.
5. Confirm no secrets, real IDs, or unrelated files are staged.
6. Commit only phase files with a Conventional Commit message and push the current feature branch.
7. Do not tag the commit.
